# 小红书 App 登录链路逆向分析

> 目标版本：com.xingin.xhs v9.36.2（jadx 全量反编译，`~/re-targets/xhs-out/jadx-out/sources/`）
> 结论均定位到 文件:行号。host 均为 `edith.xiaohongshu.com`。

## 一、短信验证码登录（3 个请求）

### 1. 发短信
```
GET /api/sns/v1/system_service/vfc_code?phone=<手机号>&zone=<区号, 如 86>&type=login
```
- 接口定义：`com/xingin/account/net/api/IVerifyCodeService.java:22`（`apiSnsV1SystemServiceVfcCodeGet`）
- 调用链：登录页 `jwa/i.java:112` → `d58/h.java` `k()` → `fr/b0.java:2439` `j0()`（"sendVerifyCode"）→ `ds/q.java:39` `c()`
- 返回 `VerifyCodeResponse`（基本只表示"已发送"）

### 2. 校验验证码，换 mobile_token
```
GET /api/sns/v1/system_service/check_code?phone=<手机号>&zone=<区号>&code=<短信验证码>&type=login
```
- 接口定义：`IVerifyCodeService.java:16`（`apiSnsV1SystemServiceCheckCodeGet`）
- 调用链：`fr/b0.java:2582` `l()`（日志名 "fetchSmsTokenNet"）→ `ds/q.java:18` `b()`
- 返回 `CheckCodeResponse`，映射为 `SmsToken{exists, token}`（`com/xingin/account/entities/g.java`）：
  - `exists=true` → 老用户，直接走第 3 步登录（`jwa/j.java:53-68`）
  - `exists=false` → 新用户，走注册 `POST /api/sns/v4/user/register`（同样带 mobile_token）

### 3. 登录
```
POST /api/sns/v4/user/login/code
Content-Type: application/x-www-form-urlencoded

mobile_token=<第2步的 token>&zone=<区号>&phone=<手机号>&<公共设备参数 map>
```
- 接口定义：`com/xingin/account/net/api/ILoginService.java:70-78`（V2 版带 `@d Map`，设备参数由 `fr.b0`/`is.a0` 填充：android_id、oaid、source、acct_group_id 等）
- 调用点：`zr/a0.java:543` `i()` ← `jwa/j.java:68`（验证码校验成功后自动触发）

## 二、用户名+密码登录（1 个请求）

```
POST /api/sns/v4/user/login/password
Content-Type: application/x-www-form-urlencoded

password=<MD5(明文密码).hex 小写>&zone=<区号>&phone=<手机号>&<公共设备参数 map>
```
- 接口定义：`ILoginService.java:88-94`
- 调用点：`n78/e.java:340` `d(zone, phone, 明文密码, source)`
- **密码不做 RSA/AES，只做 MD5**：`password = mhb.j0.c(pwd).toLowerCase()`，`j0.c()` 即 `MD5(UTF-8字节).hex`（`mhb/j0.java:47-64`）
- 相关：改密码 `api/sns/v1/user/login/password/modify`、设密码 `.../set`、重置 `.../reset`（重置需 mobile_token，即也要过短信校验）

## 三、secure 参数加密（发码/验码的"安全"变体）

`vfc_code` 和 `check_code` 都有 `?secure=<blob>` 变体（`IVerifyCodeService.java:19,25`），当风控开关 `fr.b.e()` 开启时走这条。blob 算法**已完全还原**（`fr/b.java:149-171` + `:127-139`）：

```
明文 = JSON(非空参数)                       # {"phone":"...","zone":"...","code":"...","type":"login"}
key  = MD5(deviceId.toUpperCase() + "a2901f6db8e7").hex.toUpperCase()  取前 32 字节
iv   = "9f3c8a712e0d65b4"                 # 固定 16 字节
blob = Base64( AES-256-CBC/PKCS5Padding(明文, key, iv) )
```
deviceId 即 `mhb.r.e()`（x-legacy-did 同一个值）。Python 端可独立复算。

## 四、登录态的存储与携带

登录响应（`LoginResponse`，`com/xingin/account/entity/LoginResponse.java`）关键字段：

| 字段 | 用途 |
|---|---|
| `session` | 登录会话，后续每个请求的 `x-legacy-sid` |
| `secure_session` | 网页/RN 桥等场景用（`ryc/w0.java:137`、`dla/i.java:192`） |
| `userid` / `user_token` | 用户标识 |
| `device_password` | 设备密码（免密再登录用，`/api/sns/v4/user/login/device_password`） |

- **存储**：`fr/b0.java:2409` `i0()` 把整个 UserInfo Gson 序列化后写入本地存储 `key_desc_userinfo`（`trc.h`），App 重启后恢复。
- **携带**：没有独立 Authorization 头，也不靠 Cookie。每个 API 请求由 TinyInterceptor（`n0c/p.java:77-79`）统一加：
  - `x-legacy-sid` = `IUserService.getSessionId()`（`n2c/b.java:29`，登录后即为上面的 `session`）
  - `x-legacy-did` = `mhb.r.e()`（设备 ID）
  - `x-legacy-fid` = `hjc.n1.f205613a.d()`
- 服务端鉴权 = `x-legacy-sid` + tiny/shield 签名。游客态的 session 来自 `POST /api/sns/v1/user/activate`（`ILoginService.java:23`，也返回 session/secure_session）——这解释了为什么游客能刷首页（basic homefeed 200）但搜索返回 `-100 登录已过期`：搜索接口要求正式登录 session。

## 六、对宿主机客户端（~/re-targets/xhs-out/client/）的意义

两条拿登录态的路：

1. **手动登录一次**（最省事）：模拟器 App 里走一遍短信登录，session 持久化在 `key_desc_userinfo`，签名管线每个请求自动带 `x-legacy-sid`，搜索/详情即可用。
2. **纯协议登录**：`vfc_code → check_code → login/code` 三步全走已打通的签名管线：
   - 前两个是 GET，现有 `sign(method,url,"")` 直接支持
   - `login/code` 是 POST form——**当前 sign.js 只支持无 body 的 GET，POST（body 参与 tiny 签名 + 假 chain RequestBody）需先补上**
   - 若命中 secure 变体，按第三节算法本地算 blob 拼 query 即可
   - 密码登录同理：MD5 本地算，POST 签名补上是前提
